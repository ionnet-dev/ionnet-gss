Ionnet GSS

Ionnet Game Server Studio. A game server manager: one control panel, an agent on every Host Machine, and one Docker container or stack per Game Server. Each game is a folder of configuration in a git repo, so adding a game means pushing a folder.

This page is the design we agreed in three rounds of questions, plus the defaults I filled in around them. Rows tagged you chose are settled. Rows tagged my default were my proposals, which you accepted on 2026-11-15.

Vocabulary

TermMeaning
PanelThe central web app and API. Holds users, quotas, hosts, game servers and the synced game definitions.
HostA machine that runs game servers. Enrolled by an admin. Runs Docker and the agent.
Agentgss-agent, a Go binary on each host (systemd). Dials out to the panel and drives Docker.
Game ServerOne instance of a game, owned by a user: a container (or a stack of containers) plus a data folder on the host.
DefinitionA folder with game.yml and optional hook scripts. Describes how to install, configure, start, stop and observe one game.
SourceA git repo of definitions that the panel syncs. The default one is ionnet-gss-games.
Supervisorgss-init, a small Go binary that is PID 1 in every game container. Ships in ionnet-gss-base.

A game definition

This is the file you write to add a game. The example is a proposal for the format, not a tested file.

# games/minecraft-java/game.yml
id: minecraft-java
name: "Minecraft: Java Edition"
image: ionnet-gss-minecraft-server:java{{vars.java}}   # extends ionnet-gss-base

variables:                       # the form the user fills in
  - key: flavour
    label: Server software
    type: select
    options: [vanilla, paper]
    default: paper
    reinstall: true              # changing it re-runs install
  - key: version
    label: Minecraft version
    type: select
    options_from: { hook: hooks/versions.sh }   # dynamic list
    reinstall: true
  - key: java
    type: select
    options: ["8", "17", "21", "25"]
    default: "21"
  - key: memory
    type: number
    unit: MB
    default: 2048
    bind: limits.memory          # counts against the user's RAM quota
  - key: motd
    type: string
    default: A Minecraft Server
  - key: rcon_password
    type: secret
    generate: 24                 # never shown, created once

ports:
  - { name: game, proto: tcp, default: 25565 }
  - { name: rcon, proto: tcp, internal: true }  # not published

install:
  - hook: hooks/install.sh       # resolves and downloads the right jar
  - write: { file: eula.txt, content: "eula=true\n" }

configs:                         # only these keys are managed; the rest stay the user's
  - file: server.properties
    format: properties
    set:
      server-port: "{{ports.game}}"
      motd: "{{vars.motd}}"
      enable-rcon: "true"
      rcon.port: "{{ports.rcon}}"
      rcon.password: "{{vars.rcon_password}}"

start: java -Xms512M -Xmx{{vars.memory}}M -jar server.jar nogui
ready: { log: 'Done \(\d' }
stop:  { command: stop, timeout: 60 }

console: { input: stdin }
players:
  join:  '(\w+) joined the game'
  leave: '(\w+) left the game'

backup:
  before: [save-off, save-all flush]
  after:  [save-on]
  exclude: [logs/, cache/]

A steamcmd game needs less

id: garrys-mod
image: ionnet-gss-base
install:
  - steamcmd: { app: 4020 }
ports:
  - { name: game, proto: udp, default: 27015 }
start: >
  ./srcds_run -game garrysmod -port {{ports.game}}
  +map {{vars.map}} +maxplayers {{vars.slots}}
stop: { command: quit }

A stack adds services

id: garrys-mod-mysql
extends: garrys-mod
variables:
  - { key: db_password, type: secret, generate: 24 }
services:
  db:
    image: mariadb:11
    env:
      MARIADB_DATABASE: gmod
      MARIADB_PASSWORD: "{{vars.db_password}}"
    volume: /var/lib/mysql
# the game reaches it as host "db"

How a run works

  1. Create. The user picks a host, a game and fills in the variables. The panel checks quota, allocates ports from the host's pool, generates secrets and stores the server with the definition's commit pinned.
  2. Provision. The panel sends the agent one message holding the resolved definition, hook files, variables, ports and limits. The agent creates the data folder, pulls or builds the image and creates the container with memory, CPU and PID limits, all capabilities dropped and no Docker socket.
  3. Install. gss-init starts as PID 1, reads its spec from a mounted file and runs the install steps. Output streams to the console. State is installing.
  4. Configure. Before every start, gss-init applies the configs mappings, touching only the managed keys.
  5. Start. It launches the game as uid 1000 with a pseudo-terminal. State is starting until the ready pattern matches, then running.
  6. Observe. The agent holds the unix socket to gss-init for console lines, state changes and player events, samples Docker stats every 5 seconds, and forwards everything to the panel, which fans it out to browsers.
  7. Stop. The panel asks; gss-init sends the stop command or signal, waits for the timeout, then kills. The container stays, stopped.

States

creating → installing → stopped ⇄ starting → running → stopping → stopped, with crashed and install_failed as the two failure states. Optional auto-restart on crash, with a limit of 3 in 10 minutes.

Users, quotas and hosts

  • Roles: admin (hosts, sources, users, everything) and user (own servers only). Permission keys sit under the roles so more roles can be added later.
  • Quota per user: number of servers, total RAM, total CPU, total disk, number of backups. Checked by the panel at create and at every change of a bound variable.
  • Host access: an admin grants a user access to specific hosts. A host has its own capacity and port pool; the panel refuses a server the host cannot fit.
  • Isolation: one bridge network per server (or stack), so one user's server cannot reach another's internal ports.
  • Later: sharing a server with another user at a role (view, operate, manage). The table is planned; the UI is not in v1.

How it fails

FailureWhat happens
Panel downServers keep running. Agents reconnect with backoff and replay buffered state.
Agent restartsServers keep running under gss-init. The agent reconnects to each socket and reads the console backlog from gss-init's ring buffer.
Host rebootsThe agent starts servers that were running before, per a per-server autostart flag.
Install step failsinstall_failed with the step and its output in the console. Retry re-runs install from the start.
Game crashescrashed with the exit code; auto-restart if enabled and under the limit.
Source sync breaks a definitionValidation fails at sync, the previous version stays active, the error shows on the Sources page. Existing servers are pinned and unaffected.
Host out of ports or RAMCreation is refused with a message naming the limit.
Path escape in the file managerThe agent opens the data folder as a Go os.Root and walks every path beneath it, which gives the same guarantee as openat2(RESOLVE_BENEATH) without an extra dependency. .., absolute paths and symlinks pointing out are refused; symlinks that stay inside the folder are followed.

Open questions

  1. User namespaces or a uid per server. Every game process runs as uid 1000 on the host, the same user for all tenants. Needs Docker configuration on each host.
  2. Hard disk quotas. Today a server over its limit is stopped within minutes; a hard limit needs XFS project quotas or per-server disk images.
  3. Encryption at rest for generated secrets and git tokens in the panel database.
  4. Git tokens use HTTP Basic auth and were only tested against a local git server, not GitHub or GitLab.
  5. No GitHub repo yet, images are only built locally, and nothing is deployed to hostion.
  6. Known egress limits: neighbours on public addresses are reachable, Docker's built-in DNS can resolve the host's private names, and a server cannot reach another local server through the host's public IP.

M5 design, as set in the contracts

These are my defaults, chosen so the build could start. None is built in a way that is hard to change; say so if you want one different.

TopicDecisionWhy, and the alternative
Access levelsview < operate < manage < owner. Only the owner (or an admin) can delete a server or change who it is shared with.A shared manager who could re-share or delete would effectively be a second owner. Alternative: let manage re-share.
No accessA server you have no share on answers 404, not 403.Server ids and names don't leak to other tenants.
Who paysRAM, CPU, disk, server count and backups count against the server's owner, whoever makes the change. Servers being deleted no longer count.A shared user can't spend their own quota on your server, and can't exceed yours. Alternative: count a server until the host confirms the delete.
Disk quotaCounts the sum of each server's disk limit, not measured bytes.Predictable at create time and needs no host round trip. Alternative: measured use from the stats stream.
Editing quotasA non-admin with the users permission can't edit their own quota.Otherwise they could raise their own limits.
Host grantsAdded by username (POST /api/hosts/:id/grants), like shares.Someone who manages hosts may not be allowed to list users.
Recovery codesTen single-use codes, stored hashed in their own table and consumed with one conditional update.Two requests can't spend the same code. Alternative: a JSON column on the user, which needs a row lock.
2FA and sessionsTurning 2FA on or off yourself ends no sessions. An admin reset ends all of that user's sessions.The reset is the lost-phone or compromised-account path. Alternative: end every other session when 2FA is turned on.
QR codeDrawn in the browser with qrcode-generator (MIT, no dependencies, loaded only when the setup dialog opens).The secret never goes to a third-party QR service. Alternative: a hand-written encoder, about 250 lines.
Install one-linercurl … | sudo bash; the script asks for the enrol token at a hidden prompt (or reads GSS_ENROL_TOKEN from the environment), handles Arch and Debian/Ubuntu and is safe to re-run.Changed after review: the first version put the token in sudo's arguments, where any local user could read it from the process list during the install.
nftablesThe script installs the package but never enables nftables.service.Debian's default config starts with flush ruleset, which would wipe a host's existing firewall.

M4 design, as agreed in the contracts

These are my defaults, filled in while you were away. They are built as described; say so if you want one changed.

TopicDecisionWhy
File transfersThe panel pulls or pushes a file in 512 KiB chunks over the agent's existing socket, at most 4 chunks in flight, and streams it to or from the browser over plain HTTP.The agent only dials out, so the panel must relay. The small window keeps panel memory flat however large the file is.
DownloadsThe browser asks for a single-use ticket (60 s), then opens /api/downloads/:ticket. Always sent as an attachment.A browser download cannot send the sign-in header, and this lets the browser's download manager stream the file. A user's file is never rendered on the panel's origin.
UploadsWritten to .gss/uploads/ inside the data folder and renamed into place when complete. Size limit UPLOAD_MAX_MB; refused when the disk or the server's disk limit cannot fit it.An aborted upload never leaves a half file where the game would read it.
Text editorFiles up to 2 MiB. A save is refused when the file changed since it was opened; the editor offers reload or overwrite.The game may rewrite its own config while you edit.
Backup format<server>/backups/<id>.tar.zst on the host, with the data folder and, for stacks, each service's volume.zstd is fast and pure Go. Backups stay next to the server; off-host storage is a later feature.
Backup of a running gameThe definition's before commands, a 5 s settle, archive, then the after commands, which also run when the archive fails.Minecraft must flush and pause saving, and must never be left with saving off.
Backup of a running databaseThe service container is paused while its volume is archived. If the pause fails, the backup fails.A point-in-time copy the database recovers from like a power cut. The game's queries stall for that time.
RestoreOnly while the game is stopped. The archive is extracted to a sibling folder, the swap is a journalled rename, and the game container is restarted so it sees the new folder. An interrupted swap is rolled back when the agent starts.A failed restore must not leave a half-written world.
One operation per serverOne backup or restore at a time. Start, restart, update and reinstall answer 409 meanwhile; stop is allowed during a backup.Keeps lifecycle and data operations from racing.
Backup limitA server's backups are counted against the owner's backup quota; at the limit you delete one first. No automatic rotation.The full user-wide quota arrives in M5.
MetricsCPU, memory, network and process count every 5 s, disk use every 60 s. The panel keeps the last hour in memory; nothing is stored in the database.Enough for live charts. History across panel restarts can come with schedules.
Metrics for stacksCPU and memory are summed over the containers, and so are the memory limits. Network is the game container's only.Used versus limit stays meaningful, and game to database traffic is not counted twice.
Playersgss-init matches the definition's join and leave patterns and keeps the list, which resets when the game exits. The panel shows count and names.The list survives a panel or agent restart because it lives beside the game.
AccessFiles and backups need the manage level, metrics the view level. Owners and admins have manage.Ready for server sharing in M5 without changing routes.

What the M4 review and the real runs turned up

FoundOutcome
Fake joins through chatThe first player patterns matched any line containing "X joined the game". They are now anchored at the start of the line, and allow the System chat: prefix Paper 26.3 really logs. A plugin's own broadcast with that text would still count.
Good backup shown as failedA backup finishing while the agent was disconnected could be marked failed by the panel's reconnect check. The agent's "finished" now wins over the panel's guess.
Orphan archiveA slow backup start could time out on the panel while the agent wrote the archive anyway. The agent now answers before measuring, and the panel keeps the row so it can be deleted or completed.
Paused databaseA service container whose unpause failed stayed paused. The agent now unpauses its own services at startup and after the next backup. Unit-tested only.
Restore with a service the backup lacksThe current volume is moved aside and a fresh one is created on the next start, since the backup proves the service had no data then. Unit-tested only.
Disk walksThe stats loop walked every data folder once a minute on top of the disk check. It now reads the disk check's figure, so the disk number can lag by up to a minute.
Too many playersOne server reporting an over-long list made the panel reject its whole host. The list is now cut at every hop.
Not provenA stack backup with a live database (needs the 7 GB Garry's Mod install, and a root agent to read the database's files); delete with "keep data" after M4; the 507 disk-full refusal over HTTP.
Left for hardeningTransfer slots are per host, so four users can hold all 16; huge folders are listed in one read; a rename without overwrite has a small race; a failed ticket download shows as a browser error; the Files tab shows the internal .gss folder. Listed in STRUCTURE.md.

What running real servers turned up in M3

FoundOutcome
Data root on a RAM disksteamcmd was killed at the memory limit, because files written to tmpfs count as the container's memory. The agent now warns at startup. Hosts must keep the data root on disk.
Garry's Mod packagesThe extra 32-bit packages were not needed; the base image runs the Source server as is.
Minecraft memoryPaper is killed on start at 1024 MB. The minimum is now 1536 MB.
Ports used by other softwareThe allocator handed out 27015 while another container on the host held it. Fixed: the agent reports which pool ports are bound on the host, the allocator skips them, and a bind failure retries once on the next port.
Doubled console linesThe Source server prints each warning twice on a terminal (once in red, once plain). The console shows what the game prints; nothing to fix.

Changes to the design found while building

TopicWhat changed or was added
TemplatesThe panel renders every {{…}}, merges extends, allocates ports and generates secrets. The agent and gss-init receive concrete values only.
steamcmd cacheIt cannot be mounted read-only, because steamcmd updates itself in place. To be redesigned in M3.
RCONDefinitions get console.rcon: { port, password }.
Config keysLiteral keys for properties and cfg, section.key for ini, dotted paths for json and yaml.
SecretsStored unencrypted in the panel database and never sent to the browser. Encryption at rest is open.
Sign-inbcrypt and JWT bearer tokens with a per-user token version, so a password change or disable ends existing sessions.
Web app toolingnpm instead of Deno, because of the Iontronic git dependency.
Container lifetimeThe container stays up while the game is stopped, so gss-init and the console stay reachable. Its ports stay bound on the host during that time.
SettingsChangeable only while a server is stopped; saving re-provisions it. A server keeps the definition it was created from until then.
CapabilitiesAll dropped except the six gss-init needs to own /data and switch to uid 1000: CHOWN, DAC_OVERRIDE, FOWNER, SETUID, SETGID, KILL. no-new-privileges is set.
Deleting filesA non-root agent cannot remove root-owned files a container left behind, so it deletes them from a short-lived cleanup container.
MinecraftPaper downloads use the v3 API (v2 is shut down). Default Java is 25 because Minecraft 26.3 needs it. The version field is free text; latest is resolved at install. The heap is 75% of the memory setting, which has a minimum of 1024 MB.
Console limitsOne set of limits for all three hops: 8 KiB per line, 500 lines and 1 MiB per batch. History pages backwards 500 lines at a time.
Control socketOwner-only: the socket is 0600 and its folder 0700, owned by the agent's user.
DeletingA server stays in a deleting state with its ports held until the host confirms, so a slow or offline host cannot leave an orphan or bring a deleted server back.
Template filtersUser text in a start command must use {{vars.x|sh}}; |json exists for config templates. A definition that skips the filter fails validation.
Disk limitChecked about once a minute; a server over its limit is stopped with the measured size as the reason.
steamcmdEach server keeps its own copy under its data folder (about 130 MB, counted in its disk limit). A shared writable copy would let one tenant tamper with another's install.
Dynamic dropdownsThe panel fetches the choices from an https URL the definition declares, on an allowlist of hosts, capped and cached. This replaces the hook idea in the example above. If the fetch fails, the field becomes free text checked against a pattern.
StacksService containers share the server's network under the service name, are never published, start before the game and stop after it. Default limits are 512 MB and half a core, counted against host capacity.
Git sourcesThe panel reads definition files straight from the fetched commit without checking anything out, so repository hooks, symlinks and filters never touch the panel host. Adding a source syncs it.
UpgradesA server moves to a newer definition version only while stopped, and reinstalls only when install steps or a reinstall-flagged setting changed. Values the new version rejects can be replaced in the same step. A failed upgrade puts the old spec and ports back.
Firewall self-checkThe agent lists its table every minute and rebuilds it when it is missing or different, and the Hosts page reports that check. In a test the table was back 26 s after being deleted.
Container restartsGame containers no longer restart on their own. After a reboot the agent applies the firewall rules first, then starts servers marked autostart. If the rules cannot be applied, restricted servers stay down with a reason.
Disk limit and stacksA stack's database files count toward the server's disk limit.
Validation patternsPatterns with nested or ambiguous repetition are refused when a definition is validated, so a user's value cannot stall the panel.
Images in definitionsAn image name cannot contain free-text user values; only a select with a fixed list may choose an image.
